LV4 · 기능 개선

P-05 · Claude Code 패널
지금은 [현재 모습]인데 [원하는 모습]으로 바꾸고 싶어.
필요한 내용을 나에게 물어보고 수정 프롬프트를 작성해줘.

받은 수정 프롬프트를 확인하고 구현을 요청합니다. 확인: 바뀐 기능·기존 기능.

다음 실습 준비: 스킬 전체 복사에서 grill-me 전체 저장 요청을 붙여넣습니다. .claude/skills/grill-me/SKILL.md를 확인합니다. 이름이 안 보이면 이 파일을 가리켜 사용합니다.

선택 · 추가 스킬

  • karpathy-guidelines: 가정 확인·단순한 구현·필요한 부분만 변경. Karpathy의 관찰을 정리한 커뮤니티 자료.
  • frontend-design: 디자인 방향과 글꼴·색·배치 구현.
  • webapp-testing: Playwright로 로컬 웹앱 조작·점검. 실행 도구 준비 필요, 수업에서는 소개.
  • systematic-debugging: 오류 재현·원인 조사·수정·재확인.

필요한 것 하나를 고르고 원문의 설치 방법을 확인합니다.

선택 · 내 스킬 만들기

grill-me는 기획 질문, brainstorming은 해결 방법 비교, writing-plans는 개발 단계 정리에 씁니다. 디자인 기준이나 QA 순서도 내 스킬로 만들 수 있습니다.

P-06 · Claude Code 패널
웹앱을 수정할 때마다 같은 방법으로 점검하고 싶어.
나를 인터뷰해서 점검 순서와 기준을 정하고 SKILL.md 초안을 만들어줘.
내가 확인하면 .claude/skills/webapp-check/SKILL.md로 저장해줘.

파일 내용 예시입니다. name은 이름, description은 사용 시점, 본문은 작업 순서입니다.

P-07 · 파일 내용 · .claude/skills/webapp-check/SKILL.md
---
name: webapp-check
description: 웹앱을 수정한 뒤 버튼 동작과 저장 유지 점검
---
1. 변경한 기능의 기대 결과를 확인한다.
2. 브라우저에서 직접 조작하고 저장·새로고침을 확인한다.
3. 통과·실패·미확인을 보고하고 수정할 부분을 제안한다.

저장 후 /webapp-check로 사용하고, 빠진 점검을 추가합니다.

LV7 · 나만의 Work OS with Claude API

준비: 내가 만든 CSV 보고서와 메모. CSV → 인터뷰·분석 프롬프트 → Claude 분석 → 내 메모·보고서로 연결합니다.

7-1 문제·설계

P-17 · Claude Code 패널
CSV 분석과 메모를 보고서로 연결하는 나만의 Work OS를 만들고 싶어.
Claude API가 나를 인터뷰해 분석 프롬프트를 만들고 분석하게 해줘.
/grill-me로 나를 인터뷰해서 필요한 기능과 UI/UX를 구체화해줘.

7-2 Phase별 개발

P-18 · Claude Code 패널
확인한 기획을 개발 Phase별로 나눠줘.
각 Phase의 목표와 확인할 결과를 짧게 정리해줘.
첫 Phase부터 구현하고 내가 확인하면 다음으로 넘어가줘.

확인: 첫 핵심 기능을 로컬에서 직접 사용한 뒤 다음 단계. 기본 동작이 안 되면 새 기능보다 복구를 먼저 합니다.

내 메모로 보고서 작성

P-19 · Claude Code 패널
분석 결과와 내 메모를 합쳐 보고서를 만들고 싶어.
나를 인터뷰해서 보고서의 목적과 구성을 정해줘.
내 답을 바탕으로 Claude API에 보낼 보고서 작성 프롬프트를 만들어줘.

분석 결과에 메모를 더해 보고서를 생성합니다. 받은 프롬프트를 확인하고 구현을 요청합니다. 확인: 실제 API 응답 또는 오류. API 키는 채팅·코드·ZIP에 넣지 않습니다.

7-3 QA

P-20 · Claude Code 패널

7-4 전달

P-21 · Claude Code 패널

확인: API 키 제외·압축 해제 후 실행. 브라우저에 저장한 기록은 코드 ZIP에 자동으로 담기지 않습니다.
